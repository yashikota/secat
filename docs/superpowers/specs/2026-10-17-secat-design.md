# secat 設計書

日付: 2026-10-17

## 目的と背景

`secat` は `.env` などのキー・バリュー形式のファイルを `cat` のように表示し、値の大部分をマスクする Go 製 CLI である。

主な利用者は AI エージェント（Claude Code など）である。
エージェントがファイルを読む際に、キー名・値の有無・値の種類（例: `sk-` で始まる）・値の長さは判断材料として渡したいが、秘密の値そのものはコンテキストに入れたくない。
そのため、値の先頭を少しだけ残し、残りを隠す。

`secat` は単体の CLI として配布するだけである。
エージェントに使わせる仕組み（hook、CLAUDE.md への記述など）は利用者に任せる。

## ゴール

- 元ファイルのレイアウト（行順、コメント、空行、インデント、セクション見出し、クォート、末尾カンマ）を保ったまま、値だけをマスクして出力する。
- キー・バリュー形式に見える行は、ファイル形式を問わずマスクする。
- 値の先頭を割合で残す。
- GitHub Actions の UI 操作だけでリリースできる。

## 非ゴール

- エージェント連携の仕組み（Claude Code hook、deny ルール、設定ファイル生成）は作らない。
- 各フォーマットの完全なパースや、検証、書き戻しはしない。
- キー名による選別（例: `PORT` は隠さない）はしない。すべての値を同じルールでマスクする。
- 秘密情報のスキャンや検出（gitleaks 的な機能）はしない。

## アンチゴール（動いてもこれなら失敗）

- 秘密の値が想定より多く見えること。迷ったら隠す側に倒す。特に、複数行の値の取りこぼしで生の秘密が出力されてはならない。
- 元ファイルのレイアウトが崩れ、エージェントがファイル構造を誤解すること。

## マスクのルール

- 値の長さ `n` は rune 数で数える（マルチバイト文字に対応するため）。
- 見せる文字数は `min(floor(n × ratio), max)` とする。
  - `ratio` のデフォルトは `0.25`（フラグ `--ratio`）。
  - `max` のデフォルトは `4`（フラグ `--max`）。
- 残りは元の長さ分の `*` に置き換える（長さの情報は残す）。
- 空の値は空のまま出力する。
- 短い値に対する特別なしきい値は設けない。式どおりに扱う（長さ 4 なら 1 文字見える）。

例（デフォルト設定）:

```
OPENAI_API_KEY=sk-proj-AbCdEf1234567890xyzABCD   →  OPENAI_API_KEY=sk-p***************************
DB_PASSWORD=hunter2                             →  DB_PASSWORD=h******
PORT=3000                                       →  PORT=3***
EMPTY=                                          →  EMPTY=
```

## 行の解釈（行単位の汎用パーサ）

ライブラリ（hashicorp/go-envparse など）は使わない。
それらは結果を map で返すため、コメント、順序、レイアウトが失われるからである。
そこで、1 行ずつ次の形を判定し、値の部分だけを置き換える。

| 形 | 典型的なファイル | 値の範囲 |
|---|---|---|
| `KEY=value`、`export KEY=value` | `.env` | `=` の右側 |
| `key = value` | INI、`~/.aws/credentials`、TOML、properties | `=` の右側 |
| `key: value` | YAML、properties | `:` の右側 |
| `"key": "value"`（末尾 `,` あり / なし） | 整形済み JSON | 値の文字列リテラルの中身 |

行の扱いは次のとおりとする。

- 値がクォート（`"`、`'`、`` ` ``）で囲まれている場合は、クォートを残して中身だけマスクする。
- クォートされていない値の後ろにある行末コメント（` #...`）は残してよい。ただし判定に迷う場合は、コメントも値として扱ってマスクする（安全側）。
- コメント行（`#`、`;`、`//` で始まる）、空行、`[section]` 見出し、どの形にも当てはまらない行は、そのまま出力する。
- JSON / YAML で値がオブジェクト、配列の開始（`{`、`[`）の場合は、その行をそのまま出す（中身は後続行で個別に処理される）。
- 数値、真偽値、`null` などクォートされていないスカラーも、値としてマスクする（キー名で選別しない方針と同じ）。
- キーを持たないスカラー要素の行もマスクする（実装者の判断。アンチゴールを優先した）。
  - YAML のリスト要素 `- value` は `- ` の後ろを値として扱う。
  - JSON 配列の要素 `"value",`、`123,` も値として扱う。
  - いずれも行単位で判定でき、配列の中にいるかどうかという文脈を状態として持つ必要はない。
  - Markdown の箇条書きなど設定ファイル以外を誤ってマスクしても許容する（secat の対象外）。
  - `- key: value` の形は、`- ` を除いた残りを `key: value` として扱う。

## 複数行の値（実装者の判断で安全側に倒した部分）

秘密が漏れる方向の失敗を防ぐため、少なくとも次のケースに対応する。

- クォートが行内で閉じない値（例: `.env` の `KEY="-----BEGIN ...` が次行以降に続く）は、閉じクォートが現れるまで後続行を全文マスクする。
- YAML のブロックスカラー（`key: |`、`key: >`、`|-` などの変種を含む）は、インデントがキー行以下に戻るまで後続行を全文マスクする。
- `-----BEGIN ... -----` から `-----END ... -----` までの行は、どの形式でも全文マスクする。
- TOML の `"""` / `'''` で始まり、その行で閉じない値は、閉じ記号が現れるまで後続行を全文マスクする（閉じないクォートと同じ扱い）。
- 値が行末 `\` で終わる場合（`.env`、properties の継続行）は、`\` で終わらない行が現れるまで後続行を全文マスクする。

全文マスクした行はインデントを保ち、文字を `*` に置き換える。
対応範囲は上記で確定とし、これ以上は広げない。
次の取りこぼしは許容し、README に制限として明記する。

- 1 行 JSON（minified）
- YAML の複数行プレーンスカラー（クォートもブロック記号もない値が、次の行に続くもの）

## CLI インターフェース

```
secat [flags] [file ...]
```

- ファイルを複数指定した場合は、順に連結して出力する（`cat` と同じ）。区切りヘッダは付けない。
- ファイルを指定しない場合、または `-` を指定した場合は stdin から読む。
- フラグ:
  - `--ratio float`（デフォルト `0.25`、範囲は 0〜1。範囲外ならエラー）
  - `--max int`（デフォルト `4`、0 以上。負ならエラー）
  - `--version`
- 終了コードは成功で 0 とする。読み込めないファイルがあれば stderr に出力し、残りのファイルは処理を続け、最後に 1 で終了する（`cat` と同じ）。
- フラグ解析には標準ライブラリの `flag` を使う（依存を増やさない）。

## プロジェクト構成と配布

- モジュールパスは `github.com/yashikota/secat` とする。
- マスク処理はパッケージ（例: `internal/mask`）に分け、`main` は入出力とフラグ処理だけを担う。
- テストはテーブル駆動とし、上記の各形式、クォート、複数行、マルチバイト、境界値（長さ 0〜5、ratio 0 / 1、max 0）を網羅する。
- リリースは、yashikota の Zenn 記事「GoのツールをGitHubだけでリリースできるようにする」の構成に揃える。
  - GoReleaser と svu を使う。
  - `workflow_dispatch` の `bump_type`（major / minor / patch）と `v*` tag push の両方をトリガーにする。
  - 手動実行は main ブランチからのみ許可する。
  - `permissions: contents: write`、`concurrency: release` を設定する。
  - action は commit SHA で固定する。
- CI（test、lint）は実装者の判断で用意する。
